# When does early elimination waste a tuning budget?

Declared 28 October 2026 before fitting any model or scoring these datasets. Study46 of the separate fifty-study program. A computational research comparison, not a deployment forecast or an algorithm novelty claim.

## Decision, acceptance and sources

An analytics team can spend a limited search allowance either screening more configurations cheaply or fitting fewer configurations to completion. Compare fixed-budget random search with successive halving, recording performance variability, actual time and whether early elimination discards a configuration that would win after full training. Success means a complete auditable comparison, including negative findings; neither strategy is required to win.

Use four exact active numerical-regression OpenML datasets listed in benchmark suite336: development datasets diamonds44140v6 (metadata:public domain) and house_sales44144v8 (CC0); dataset-level evaluation datasets superconduct44148v4 (CC BY4.0) and delays_zurich_transport45034v3 (CCZero). Dataset choices follow numerical format, explicit metadata rights and distinct domains, not observed model performance. Preserve the suite's in_preparation status; individual datasets are active. Retain exact source metadata, ARFF URLs, download times and SHA-256 hashes. Attribute the OpenML benchmark transformation and original creators, including Kam Hamidieh's UCI superconductivity dataset DOI10.24432/C53P47. Do not redistribute source papers or manuscripts. Only reviewed eligible numerical panels and original code may be public.

These are benchmark-transformed tables. Use targets and feature units exactly as distributed and call them benchmark target units unless an original-unit correspondence is independently established. Do not claim original USD, kelvin or delay-time errors merely from an original dataset description. No clinical/personal data, addresses or route identities are needed. The comparison's value is search-allocation evidence, not validation of property valuation, material discovery or transport deployment.

Read source rows with scipy ARFF into numeric values; exclude target and metadata-declared ignore/row-ID attributes, plus exact case-insensitive names id/date. Keep finite targets, reject infinite features and retain missing feature values for native estimator handling. Drop exact full-row duplicates. Group identical predictor vectors, including canonical missing values, so conflicting targets or repeats cannot cross partitions. Hash each predictor vector using little-endian float64 bytes with canonical NaN; use the same source feature order. Select groups by hash order until their cumulative rows would exceed6,000, then stop. Export all inclusion/exclusion counts and source-row identities. The bounded hash sample is not a full-dataset benchmark.

For six declared seeds110,211,312,413,514,615, assign whole feature groups by SHA256(group hash + colon + seed), first8hex modulo10: buckets0--5 fit,6--7 validation,8--9 final test. No target-dependent splitting. Check group disjointness, row/target integrity and minimum200 observations in each partition. Random grouping does not resolve unobserved house, material-family, route or time dependence; results are conditional resampling comparisons, not independent deployment or future-period evidence. Repeated-seed tests overlap and must not be pooled as independent datasets.

## Model and declared search budget

One model family keeps the resource comparison interpretable: HistGradientBoostingRegressor, squared-error loss, early_stopping=False, max_bins64, max_depth=None, random_state=seed, single-thread execution. No feature scaling/imputation is learned outside fitting. Native missing-value handling is used. Center and scale the target by fitting-only population mean/SD; invert predictions for exported errors. HGB need not scale predictors. Final refits recompute target mean/SD on fit+validation only. Baseline is the fit+validation target mean.

The36-setting finite space crosses learning_rate{0.03,0.10,0.30},max_leaf_nodes{7,15,31},l2_regularization{0,1},min_samples_leaf{10,30}. For each dataset/seed, NumPy default_rng(seed+dataset_id) permutes the canonical lexicographic configuration list and retains the first18. Candidate IDs encode exact parameters. Both strategies receive this same pool. Fixed-budget random search fits the first6 at90iterations. Successive halving fits all18 at10iterations, the best6 at30 and the best2 at90. Every stage is a fresh cold fit, no warm-start or caching. Each search uses exactly540 requested boosting iterations (6x90 versus18x10+6x30+2x90). Iterations are a resource proxy, not equal FLOPs, energy, wall time or money: tree size and preprocessing costs vary. Record per-fit elapsed time and actual n_iter_, plus search-only and end-to-end time separately. No paid compute.

Select by minimum validation MSE in original distributed target units at the final90-iteration stage, ties by candidate ID. Promote similarly by stage validation MSE. Non-finite scores or fit errors remain logged, never removed; a failed configuration is ranked after successful configurations. Stop a run and report incomplete if fewer candidates can be promoted or its full declared resource comparison cannot execute. Do not relax budgets or silently resample. No best-strategy choice is made from final-test results.

After each search's selection is recorded, audit all18 candidates at90iterations on the same fit/validation partition. This extra research computation is explicitly outside both search budgets and is never used to change the recorded selections. Retain every audit candidate, validation prediction and MSE. Quantify the selected validation regret relative to the best full-budget candidate in that finite pool, and whether the halving promotions discard that candidate at10 or30iterations. This is a finite validation oracle, not a global optimum or a test oracle. Report the audit's extra iterations and time; do not present the entire experiment as costing only540iterations.

## Protected evaluation and evidence

First execute development datasets and verify the implementation. Freeze its configuration, source/split manifests, search rules, selected candidates and audit metrics before evaluating any test row. Any repair after test inspection makes affected reused tests retrospective. Then run the unchanged protocol for the two held datasets and freeze their selectors before scoring their tests. Fit each selected configuration at90iterations on fit+validation; evaluate only the two frozen strategies and the fixed mean baseline on test.

Export every fitting-stage validation prediction, exact split/group IDs, selected configuration, final observation-level prediction/label, actual settings, statuses, iteration accounting and runtimes. Report MSE, RMSE, MAE, mean signed error and MSE divided by outer-training target variance. Report per-dataset paired strategy differences for all six seeds and median/range summaries. No p-value or nominal independent confidence interval across overlapping seeds; four datasets cannot establish a population-wide search-strategy winner. Report each dataset separately, development versus held-dataset role, search variability, boundary settings and all unfavorable outcomes. Do not pool differently scaled targets into raw MSE.

## Prior work and claimed contribution

Random search and successive halving are established. Hyperband explicitly studies adaptive resource allocation; this is a small cold-fit, iteration-matched comparison with an extra full-pool validation audit, not an implementation or reproduction of full Hyperband. Scikit-learn documents that too little early resource can fail to discriminate configurations. The empirical question is which of these declared settings and datasets exhibits that risk, and what the observed search/time tradeoff is. No exhaustive literature-gap claim is made.
